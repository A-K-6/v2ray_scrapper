v2rays_

Scrape proxy subscriptions, test every node through a real sing-box core, and serve only the working ones. One static binary — no Docker, no Redis.

01Three commands to working proxies

v2rays config init # first-time setup (config, token, sing-box) v2rays doctor # health check v2rays tui # easiest: interactive menu

02Usage

serve

Run the HTTP API (default). Same endpoints as the Docker image, Swagger at /swagger.

refresh

One scrape + test cycle, then export. --out sub.txt --format base64 --country US,DE.

get

Export the cached results without touching the network. Formats: raw, base64, json.

test

Ad-hoc test of a subscription URL or file: test --sub URL --limit 50.

sources · sites

list | add | rm subscription feeds and site-specific checks. Persisted locally, no Redis needed.

token · config · doctor

Manage MANAGEMENT_TOKEN, inspect paths, and verify sing-box, GeoIP, state and token health.

03How it works

1

Scrape

Fetches every configured subscription feed (SUB_URLS), decodes raw/Base64 payloads and parses VLESS, VMess, Trojan, Shadowsocks and Hysteria2 URIs into structured nodes. Duplicates are merged.

2

Test through sing-box

Nodes are grouped into batches (default 100). Each batch gets a real sing-box process with one SOCKS inbound per node, then every node performs genuine HTTPS probes — not pings. Failures die on the first probe; survivors must pass twice. Concurrency is bounded so a 10,000-node cycle can't melt small hosts.

3

Enrich & rank

Working nodes get a MaxMind GeoIP lookup (country code + flag) and a remark like 🇩🇪 DE 142ms, then are sorted by latency and persisted atomically to state.json.

4

Serve & publish

The REST API serves top-25 / full / country-filtered / site-specific subscriptions as JSON, raw or Base64. Optionally the verified list is pushed to a Git repo, with one file per preloaded site. A background ticker refreshes everything on CACHE_INTERVAL_SECONDS (default 10 min).

Storage: in-memory cache + atomic JSON state always; source/site management lives in Redis when REDIS_URL is set (Docker), otherwise in a local registry.json file. Same behavior, zero infrastructure.

04Configuration

Standalone settings live in ~/.config/v2rays/.env (auto-loaded; v2rays config init manages it). Data lives under ~/.local/share/v2rays/. All values also work as plain environment variables.
